Step 1 数据收集 zqy

从 LIHKG / YouTube 留言 / 小红书香港区收集粤英混码评论，目标 300 条（目前已有 30+ 条）。筛选标准：每句至少含一个英文词，纯粤语或纯英文不算。

整理格式：每行一句，存成 .txt 或 .csv，列名 sentence_id | raw_text

↓300条原始句子交给 pyt
Step 2 PyCantonese 自动标注（生成待修正数据） pyt

用 PyCantonese 对全部 300 句做自动 POS 标注，输出每个 token 的标注结果。同时用正则识别语言（ASCII = EN / 其余 = ZH），标记每个 token 的语言 ID。

pc.pos_tag(sentence) → [(token, lang_id, auto_pos), ...]

输出格式交给 lyl：token | lang_id | auto_pos | gold_pos（空白待填）

同时记录哪些句子含英文词、英文词占比，作为数据集统计（用于 report dataset 章节）。

↓带 auto_pos 的标注文件交给 lyl
Step 3 人工修正 → 建立 Gold Standard lyl

只需检查英文 token 的 auto_pos 是否正确，粤语部分直接保留 PyCantonese 结果。将错误的标注手动改成正确词性，填入 gold_pos 列。

同时统计错误类型（如：NOUN 误标为其他、VERB 被标为 NOUN 等），这些错误案例就是 rule-based 方法的设计依据，也是 report 里 Baseline Analysis 的核心内容。

完成后的文件即为整个项目的 Gold Standard 数据集，供 lyl 自己、zxy、szq 三人共用。

↓Gold Standard 数据集分发给下方三人
Step 4a Rule-based 修正 lyl

根据 Step 3 的错误统计，设计消歧规则（前后粤语词 POS / 体貌助词 咗·緊·過 等），写成 post-processing patch，在 PyCantonese 输出上修正英文词标注。

baseline → +rules → F1↑
Step 4b BiLSTM-CRF zxy

以 Gold Standard 训练 BiLSTM-CRF（240/30/30 分割），输入特征含词嵌入 + 语言ID。CRF 层保证标注序列合法，捕捉长距离粤语上下文依存。

torchcrf + PyTorch
Step 4c mBERT fine-tune szq

fine-tune bert-base-multilingual-cased，用 BertForTokenClassification，处理 subword 对齐问题（每词取首个 subword 的预测），在同一数据集上训练。

HuggingFace Transformers
↓四个系统的预测结果汇总给 pyt
Step 5 评估 & 结果分析 pyt

整合四个系统（Baseline / +Rules / BiLSTM-CRF / mBERT）在测试集上的预测结果，统一计算 Accuracy / Precision / Recall / F1（per-class）。制作对比表格和混淆矩阵，挑选定性例子展示各系统在同一句的不同输出。

sklearn.metrics → classification_report
